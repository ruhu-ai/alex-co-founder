# 10 — Demo UI

One static page (`app/static/index.html`), no framework, no build step. Its job is
to make the agent's work **visible** for the video and judges: the board, the
conversation, the review controls, the approval gate, and the adaptation proof.
`adk web` remains the dev inspection surface and is never deployed.

**Visual and interaction rules live in `16-design-system.md`** — colour tokens and
the contrast contract, the type scale, the Phosphor icon sprite, component
primitives (`.btn`, `.badge`, `.card`, `.dialog`, `.meter`), layout breakpoints,
motion and accessibility. This doc specifies *what* the surface does; that one
specifies *how it looks and behaves*. Two checks guard it in CI:
`scripts/check_contrast.py` and `scripts/build_icons.py`.

The left cell hosts two surfaces: **Pipeline** (default) and **Browser** (the
live watch view, 18) — never both. The header globe toggles them; the Browser
surface auto-opens when a run starts. The hairline between left cell and chat
is a drag handle (pointer + keyboard, width persisted). Below 960px the
surfaces become pane tabs (Pipeline / Chat / Browser).

## Components → endpoints

| Component | Talks to | Notes |
|---|---|---|
| Chat | `POST /wake`, `POST /session/new` | renders agent text; tool chips from event stream if exposed, else simple transcript. **Mic button** records a voice note (webm) and posts it to `POST /api/voice-note`; the transcript + extracted intent render as a user message. **Talk button (🎙️)** opens a real-time voice conversation over `WS /live/{session_id}` — Gemini Live bidi-streaming on the SAME orchestrator/session, with live captions in the chat log and barge-in support |
| Pipeline board | `GET /api/pipeline` | columns: URGENT, SHORTLISTED, ARCHIVED (reason tooltip), plus in-flight applications with `current_step` badges |
| Doc intake | `POST /api/ingest`, `GET /api/ingest/{ref}`, then `POST /wake` with `attachment_refs` | Paperclip accepts PDF/DOCX/PPTX/XLSX/TXT/CSV. Scope defaults to **Use in conversation**; **Add to Founder Profile** is explicit. The 202 response registers an owner/session-bound ref; bounded UI status observation never blocks chat. READY shows cited-section counts, profile scope shows exact apply/review counts, and NO_TEXT/UNSUPPORTED/FAILED never claim the file was read. Raw filenames have no authority. |
| Review panel | `GET /api/applications/{id}`, `POST /api/feedback` | per section: draft text, **drafter notes ("why this draft looks this way")**, Gemma Evidence Check findings from the current version only (20), Approve / Edit (inline textarea) / Reject (reason required — button disabled until filled) |
| Fill report | `GET /api/applications/{id}` | filled/total, needs_human list, **recon `form_map` link** — what the vision recon discovered (fields, steps, requirements), shown before the fill report. Browser evidence selects the retained frame in the Browser surface; screenshots are not rendered or opened from the review panel |
| Browser surface | `GET /api/browser/state`, `GET /api/browser/events`, `POST /api/browser/stop` | left-cell observation surface (18/22): typeable URL bar (Enter → composes the chat request; never navigates directly), goal, snapshot-first event stream, ordered viewport-frame timeline, last action, **Stop** for nonterminal browse and fill runs. It auto-opens when a run starts; close returns to Pipeline. Arbitrary remote content is never iframed |
| Approval modal | `POST /api/approvals/{id}/resolve` | appears when application enters AWAITING_SUBMIT_APPROVAL; Approve → token minted server-side |
| Audit tail | `GET /api/audit` | last 15 audit rows with relative timestamps — judges love this |
| Documents | `GET /api/documents` | produced files (docx/xlsx/pptx) grouped by application with version + session tag; in-chat, artifact links render as download cards (15) |
| Theme toggle | — | light + dark via semantic tokens (docs/16 §1). Three resolution states: no stamp follows the OS, an explicit choice is stamped on `<html>` and persisted in `localStorage` |

## Review panel shape

Pinned (always visible): approval gate, stepper, draft sections and their
current Evidence Check findings — everything the founder acts on. Tabbed below
(`docs/16 §7.10`): **The form** (recon evidence +
fill report), **Documents**, **Activity**. Tab labels carry counts and an amber
dot when a section needs the founder, so a closed tab can still ask for
attention. The approval gate is never inside a tabpanel.

## The adaptation money shot (must be visible)

Under every draft section, render `notes` from `save_draft_section` as a quoted
line, e.g.:

> *"Avoided 'revolutionary' — your feedback of Aug 20: 'sounds like a scam pitch'."*

This single UI line is the Collaborative Partner proof. Seed the underlying
rejection via `scripts/seed_demo.py` so the demo never depends on remembering
to manufacture it live.

## Behavior rules

- Pipeline/application state refreshes on boot, founder activity, explicit
  mutations, focus, and visibility restore. Browser state is snapshot-first
  SSE while the authenticated page is visible (22); there is no periodic
  browser-state poll or background agent wake.
- After `POST /api/feedback`, the chat shows the agent's resumed reply (the
  endpoint returns the wake result), so feedback → agent reaction feels live.
- Everything read-only is safe to refresh; every mutation button confirms first.
- Attachment status observation is a bounded UI projection of durable records,
  not an agent poll or workflow wake. On each founder turn the server refreshes
  registered refs so a completed background extraction cannot remain stale in
  session state.
- Production upload registration returns before its Cloud Task runs. The local
  no-queue fallback is request-bound and may return an already-terminal status;
  the same status renderer handles both without optimistic copy.
- Copy is founder-voice ("Your co-founder", "Needs you") — no agent jargon,
  no third-party logos (submission rule).

- [x] Reject without a reason is impossible in the UI.
- [x] Approval modal cannot be bypassed: no submit button exists outside the modal flow; the only path mints a token via `resolve`.
- [ ] Adaptation line renders on the second draft of the seeded scenario.
- [ ] Page works at Cloud Run URL with only Firestore + the two services up (no local dependencies).
- [x] Attachment registration returns immediately, chat remains usable while
