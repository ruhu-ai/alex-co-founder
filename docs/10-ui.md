# 10 — Demo UI

One static page (`app/static/index.html`), no framework, no build step. Its job is
to make the agent's work **visible** for the video and judges: the board, the
conversation, the review controls, the approval gate, and the adaptation proof.
`adk web` remains the dev inspection surface and is never deployed.

**Visual and interaction rules live in `16-design-system.md`** — colour tokens and
the contrast contract, the type scale, the Phosphor icon sprite, component
primitives (`.btn`, `.badge`, `.card`, `.dialog`, `.meter`), layout breakpoints,
motion and accessibility. This doc specifies *what* the surface does; that one
specifies *how it looks and behaves*. Two checks guard it in CI:
`scripts/check_contrast.py` and `scripts/build_icons.py`.

## Components → endpoints

| Component | Talks to | Notes |
|---|---|---|
| Chat | `POST /wake`, `POST /session/new` | renders agent text; tool chips from event stream if exposed, else simple transcript. **Mic button** records a voice note (webm) and posts it to `POST /api/voice-note`; the transcript + extracted intent render as a user message. **Talk button (🎙️)** opens a real-time voice conversation over `WS /live/{session_id}` — Gemini Live bidi-streaming on the SAME orchestrator/session, with live captions in the chat log and barge-in support |
| Pipeline board | `GET /api/pipeline` | columns: URGENT, SHORTLISTED, ARCHIVED (reason tooltip), plus in-flight applications with `current_step` badges |
| Doc intake | `POST /wake` (+ artifact upload) | **Upload button** for company documents (deck, plan, model, past applications); ingestion proposals render as an approve/reject-per-item list in the review panel (reject requires a reason — same control semantics as section feedback) |
| Review panel | `GET /api/applications/{id}`, `POST /api/feedback` | per section: draft text, **drafter notes ("why this draft looks this way")**, Approve / Edit (inline textarea) / Reject (reason required — button disabled until filled) |
| Fill report | `GET /api/applications/{id}` | filled/total, needs_human list, screenshot links (artifact URLs), **recon `form_map` link** — what the vision recon discovered (fields, steps, requirements), shown before the fill report |
| Browser panel | `GET /api/browser/state`, `POST /api/browser/stop` | live view of any browser work (18): read-only URL bar, goal, latest screenshot (refresh on the 5 s poll), last action, **Stop browsing**. Renders atop the review panel whenever a browse/fill session is active |
| Approval modal | `POST /api/approvals/{id}/resolve` | appears when application enters AWAITING_SUBMIT_APPROVAL; Approve → token minted server-side |
| Audit tail | `GET /api/audit` | last 15 audit rows with relative timestamps — judges love this |
| Documents | `GET /api/documents` | produced files (docx/xlsx/pptx) grouped by application with version + session tag; in-chat, artifact links render as download cards (15) |
| Theme toggle | — | light + dark via semantic tokens (docs/16 §1). Three resolution states: no stamp follows the OS, an explicit choice is stamped on `<html>` and persisted in `localStorage` |

## The adaptation money shot (must be visible)

Under every draft section, render `notes` from `save_draft_section` as a quoted
line, e.g.:

> *"Avoided 'revolutionary' — your feedback of Aug 20: 'sounds like a scam pitch'."*

This single UI line is the Collaborative Partner proof. Seed the underlying
rejection via `scripts/seed_demo.py` so the demo never depends on remembering
to manufacture it live.

## Behavior rules

- Poll `GET /api/pipeline` + active application every 5 s (simple, demo-adequate).
- After `POST /api/feedback`, the chat shows the agent's resumed reply (the
  endpoint returns the wake result), so feedback → agent reaction feels live.
- Everything read-only is safe to refresh; every mutation button confirms first.
- Copy is founder-voice ("Your co-founder", "Needs you") — no agent jargon,
  no third-party logos (submission rule).

## Acceptance checks

- [ ] Full demo script (09 §demo sequence) executable through the UI without touching `adk web` or curl.
- [x] Reject without a reason is impossible in the UI.
- [x] Approval modal cannot be bypassed: no submit button exists outside the modal flow; the only path mints a token via `resolve`.
- [ ] Adaptation line renders on the second draft of the seeded scenario.
- [ ] Page works at Cloud Run URL with only Firestore + the two services up (no local dependencies).
